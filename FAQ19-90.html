サーバ移行の手順のうちバックアップ1～7の中でサービス停止しなくても正常に行える項目は？ new!

「サポート２」でダウンロードできる技術資料「メールサーバ・SMTP サーバ移行の手順について」（Std (x64) 版・Ent (x64) 版）では、「A. バックアップの要点」で「バックアップは、E-Post 関係の全サービスを停止させた上でバックアップ作業を行ってください。」と案内しています。これについて、バックアップ手順1.～7.の中に、サービスを停止しなくても正常にバックアップを行える項目はあるか、というご質問をいただいたことがあります。
なお、Std (x64) 版・Ent (x64) 版とも、バックアップ手順1.～7.の構成は同じです。

前提：サービスが動いている間は、フォルダの中身が刻々と変わっています
サービスが動作している間は、メールのSMTP受領・配送・リトライなどの処理が進むため、メール作業フォルダやメールボックスフォルダの中では、ファイルの生成・リネーム・削除・移動が刻々と行われています。サービスが動いていてもファイルのコピー自体は取れますが、作業途中のファイルや作成途上のファイルが含まれる可能性があり、リストアしても完全に元に戻せる保証はありません。
一方、人為的に設定変更をしない限り内容が変わらないものについては、サービスを停止しなくてもバックアップを取ることができます。この観点で、手順1.～7.を整理すると次のとおりです。

手順バックアップ項目停止せずに可補足
1Mail Server の基本設定内容のバックアップ○停止しなくてよい
2プログラムインストールフォルダ下にある設定ファイル群のバックアップ○（△）原則停止しなくてよい。ロックアウト機能を使用している場合は注意
3ユーザーアカウント情報（アカウントデータファイル）のバックアップ○停止しなくてよい
4メール作業データのバックアップ×サービス停止が前提
5ユーザーごとのメール関連の設定、メールデータのバックアップ×（△）メールデータはサービス停止が前提。設定ファイル類は停止しなくてよい
6登録済みドメインの方式を確認○確認のみのため停止しなくてよい
7hosts ファイルのバックアップ○停止しなくてよい
○：サービスを停止しなくてもバックアップ可能　×：事前にサービスを停止することが前提　△：条件付き（各項目の説明を参照）

1.Mail Server の基本設定内容のバックアップ
E-Post Mail Controlの「バージョン情報」タブにある［エクスポート］ボタンで出力される "epst-ms.reg" ファイルのバックアップです。基本設定の内容の出力であり、基本設定はふだん変更することがないものですので、サービスを停止せずにそのままバックアップを取ってかまいません。

2.プログラムインストールフォルダ下にある設定ファイル群のバックアップ
拡張子.datの設定ファイル類（【sender.dat】【effect.dat】【gateway.dat】【mail.dat】等）のほとんどは、人為的な設定変更をしない限り変動がないため、サービスを停止せずにそのままバックアップを取ることができます。任意のフォルダに置いているSSL用の証明書ファイルや秘密鍵ファイルも同様です。
ただし、【mail.dat】設定において Level:xx1 という n=xx1 の指定を行っている場合、拒否したメールやタグを付けたメールの送信元IPアドレスが【effect.dat】に自動的に追加登録されていきますので、こうしたケースでは【effect.dat】は除外してください。バックアップ後のアクセスにより、【effect.dat】の内容が追加・変更されている可能性があります。さらにIPロックアウト機能・認証接続ロックアウト機能を使用している場合は注意が必要です。これらの機能で使われる設定ファイル（"rejectsmtpip.dat"、"rejectpopip.dat"、"rejectimapip.dat"等）は、設定ファイルであると同時に、SMTP・POP3・IMAP4それぞれの接続や認証のたびに記録が追加・更新されていくトランザクションのテーブルとしても働いています。そのため、サービスを停止しないままバックアップを取った場合、バックアップを取った後のアクセスによって、内容が追加・変更されている可能性があります。
なお、IPロックアウト機能・認証接続ロックアウト機能を使用していない場合は、この点は関係ありません。

3.ユーザーアカウント情報（アカウントデータファイル）のバックアップ
アカウントデータファイル（"[ドメイン名].idx"）は、人為的に追加や設定をしない限り変動がないため、サービスを停止せずにそのままバックアップを取ることができます。

4.メール作業データのバックアップ
メール作業フォルダ（デフォルトC:\mail）は、大別すると次のような種類のフォルダで構成されています。
・共有設定情報を保管するregフォルダ
・ログ関係のフォルダ
・SMTP受領の一時作業フォルダ
・メールキューフォルダ
・リトライ関係の作業フォルダ
・メーリングリストの配送展開フォルダ
・MXキャッシュフォルダ
・その他
サービスが動作したままでは、SMTP受領・配送・リトライなどの一連の動作が進行し、時間の経過とともにどんどん構成内容が変わっていきます。また、regフォルダの中には、メールのメッセージIDの発番情報を保管しているファイルもあり、このファイルはSMTP受領のたびにカウントアップされるため、中身が常時変更されています。
ほとんど変更がないフォルダもありますが、サービスを動作させたままバックアップを取った場合、リストアしても完全に元に戻せる保証はありません。メール作業データのバックアップは、事前にサービスを停止することを前提にお考えください。

5.ユーザーごとのメール関連の設定、メールデータのバックアップ
これはメールボックスフォルダのバックアップになります（メールボックスフォルダがメール作業フォルダの下にある既定の設定の場合は、上記4.に含まれます）。サービスが動作していると、メールデータファイルが格納されたり、ユーザーの操作によってメールデータファイルの消去・移動・リネームなどが刻々と行われ、構成が変化していきます。メールデータのバックアップは、事前にサービスを停止することを前提にお考えください。
ただし、メールボックスフォルダ内に置かれている次の設定ファイル類は、人為的に設定変更しなければほとんど変わらないため、サービスを停止せずにバックアップを取ってかまいません。
・自動転送・自動応答設定ファイル（IMS.CTL）
・SMTP AUTH／APOPパスワードファイル（apop.dat）
・送信先制限設定ファイル（sender.dat）　など

6.登録済みドメインの方式を確認
確認だけですので、サービスを停止する必要はありません。

7.hosts ファイルのバックアップ
人為的に設定変更しなければ変わらないため、サービスを停止せずにバックアップを取ってかまいません。

※「サービスを停止しなくてよい」としている項目も、人為的な設定変更をしないことが前提です。バックアップ作業中は、設定の変更を行わないようにしてください。
※MSFCクラスタ構成の場合は、E-Postのサービスを停止するとクラスタの制御が切り替わってしまうため、サービスの停止方法が異なります。移行手順の資料の「A. バックアップの要点」、および下記記事「[32bit版][64bit版] MSFCクラスタ構成でサーバ移行時のバックアップ作業前に行うサービス停止について」を参照してください。
