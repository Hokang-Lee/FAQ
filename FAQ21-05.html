OAuth2.0 Gateway 設定ガイドに記載されているAPIの登録で、SMTP_SendのAPIは「Microsoft Graph」のSMTP.Sendで間違いないか new!

Microsoft 365とOAuth2.0を使用し、E-Post SMTP Serverをメール中継サーバとして構築している環境で、setoauth2.exeを実行するとトークン関連ファイルは正常に作成されるものの、Statusが「Authentication unsuccessful」になる場合があります。このとき、SMTP_SendのAPIとして「Microsoft Graph」のSMTP.Sendを登録するのか、「Office 365 Exchange Online」のSMTP.Sendを登録するのか、というご質問をいただいたことがあります。

登録するAPIは、「Microsoft Graph」のSMTP.Sendで間違いありません。

1. 構成されたアクセス許可を確認する
Microsoft 365でSMTPのOAuth認証を使用する場合は、［APIのアクセス許可］-［構成されたアクセス許可］に、「Microsoft Graph」の次の3つのアクセス許可を登録してください。種類はいずれも「委任済み」です。
・offline_access
・SMTP.Send
・User.Read


2. トークン関連ファイルの生成状況を確認する
setoauth2.exeの実行後、次のファイルが正常に作成されているか確認してください。これらが作成されていてもStatusが「Authentication unsuccessful」となる場合は、トークンの取得処理ではなく、SMTP AUTHの認証段階でMicrosoft 365側から拒否されている可能性があります。
・code.txt
・access_token.dat
・refresh_token.dat
・xoauth2_code.dat
Status: Authentication unsuccessful

3. Microsoft 365側の関連設定を確認する
同じ症状が発生する場合は、APIの登録に加えて、Microsoft 365側の次の設定も確認してください。
・認可サイトへのアプリの登録
・APIの登録
・テナントの設定
・使用するメールアカウントでのSMTP AUTHの有効化
・セキュリティの既定値群の無効化

（注意事項）
本項のAPI登録では、「Office 365 Exchange Online」のSMTP.Sendではなく、「Microsoft Graph」のSMTP.Sendを選択します。上記3種類のアクセス許可とMicrosoft 365側の関連設定を確認しても改善しない場合は、実際の設定内容とsetoauth2.exeの実行結果を添えてサポートへお問い合わせください。
