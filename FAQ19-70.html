IISのSMTPサーバ機能に用意されていた匿名アクセス設定機能と同じことができないか new!

Windows Server内蔵のIIS「SMTPサーバ機能」における受信側設定［匿名アクセス］などで、クライアントから認証要求があっても無条件に許可する設定ができた。E-Postシリーズでも同じことが可能か。というご質問をいただいたことがあります。
E-PostシリーズはIISのSMTPサーバと完全互換ではありません。また開発思想も異なります。
認証要求があるにもかかわらず、IISのSMTPサーバのように［匿名アクセス］と呼ばれる機能で無条件にアクセスを許可することはE-Postではできません。E-Postシリーズは仕様上、クライアントからSMTP認証要求があると、それに従い必ず認証チェックが入ります。
ただし同様の近いことはできます。IISからの移行で同等の運用をしたい場合は、次の対応方法があります。

1.【effect.dat】による記述で設定する方法
E-Post Mail Control－「中継の制限」タブ画面にある［マシン毎の中継］【effect.dat】に接続元のローカルIPアドレスを無条件許可する方法です。個別のIPアドレスを指定する以外にワイルドカードが使用できます。
（例その1）
192.168.101.201 true
（例その2）
192.168.101.* true
（例その3）
192.168.*.* true

2.サーバ全体で非認証有効を設定する方法
E-Post Mail Control－「サービス制御」タブ画面にある［SMTP認証方法］下の［セキュリティレベル］を［非認証有効］とする方法です。変更後はEPSTRSサービスを再起動します。
これにより、上記1とは同じではありませんが、メールクライアントはSMTP認証ありでもSMTP認証なしでも、非認証有効状態でメールを送信できるようになります。しかし、この設定はサーバ全体の設定ですので、外部に接続しているメールサーバやSMTPサーバでは不正利用の可能性が高くなりきわめて危険です。この設定を行うときは外部に接続していないことが担保できているサーバで行ってください。
